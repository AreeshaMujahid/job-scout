# Job Scout

Reads your CV, searches six job boards with terms taken from it, and scores
what comes back — telling you why each posting fits and what you are missing.
Then it helps you actually apply: a cover letter, your own CV with this
posting's wording swapped in, and drafts for the open questions on the form.

Two pieces:

| | |
|---|---|
| **`job_scout/`** | A stateless Python service. Reads CVs, searches boards, scores jobs, writes letters, edits PDFs. Owns no data. |
| **`jobscout-web/`** | The web app. Owns the database: users, CVs, scores, the tracker. |
| **`linkedin.py`** | Scrapers for LinkedIn, Xing and Arbeitnow, imported by `job_scout/sources/scrapers.py` rather than reimplemented. Without it those three boards are simply absent and the rest still works. |

```
Browser ──► Next.js ──► Postgres
               │
               ▼  HTTP
         Python service ──► Gemini / Claude
```

The split is deliberate. The Python service keeps nothing, so it can be
restarted or moved without consequence; everything worth keeping lives in the
web app's Postgres.

## Running it

Two processes. The Python service first, because the app calls it:

```bash
pip install -r job_scout/requirements.txt
python -m job_scout.service
```

Referral lookups additionally need `playwright install chromium`; everything
else runs without it.

```bash
npm install --prefix jobscout-web
npm run dev --prefix jobscout-web
```

Then <http://localhost:3000>.

**No database setup.** With `DATABASE_URL` unset the app runs PGlite —
Postgres compiled to WASM — in `jobscout-web/.pglite`. Same SQL, no Docker,
no connection string.

**No mail server needed locally.** Sign-in, confirmation and password-reset
links are printed to the terminal and shown on screen. That fallback is
disabled when `NODE_ENV=production`.

Copy `jobscout-web/.env.example` to `jobscout-web/.env.local` to change
anything; the defaults work as they are.

### A note on typechecking a fresh clone

`npx tsc --noEmit` on a clone that has never been run reports `Cannot find
name 'PageProps'` half a dozen times. Those types are generated by Next into
`.next/types/`, which `tsconfig.json` includes. Start the dev server once and
they appear. Nothing is wrong with the code.

## Deploying

```bash
cp .env.docker.example .env      # then fill it in
docker compose up -d --build
```

Four containers: Postgres, the Python service, the web app, and the inbox
worker. Only the web app is published to the host — put a TLS terminator in
front of it.

Compose refuses to start rather than booting half-configured, so a missing
secret is a clear error instead of a subtle one.

## What it does

- **Search and score** — six boards, deduped into one row per posting, rated
  in batches against your CV with sub-scores and an opening line
- **Tailor your CV** — edits your real PDF *in place*, so the photo, fonts
  and column alignment survive. A skills line with no room gains a new line
  rather than losing the keyword
- **Cover letters and referrals** — drafted per posting; referral contacts
  looked up on LinkedIn
- **Application questions** — a chat panel that drafts answers to the open
  boxes on a form, from your CV and the posting, and refuses to claim
  anything your CV does not evidence
- **Tracker** — saved → applied → interviewing → offer → rejected
- **Inbox tracking** — forward your application mail to a per-user address
  and the tracker keeps itself up to date, showing the sentence that moved
  each row (needs a domain with MX records)
- **Admin panel** — health, counts, and per-user support actions

## Built with

**Python:** FastAPI · Pydantic · PyMuPDF · BeautifulSoup · Playwright · requests · Streamlit
(the standalone UI) · Gemini through its OpenAI-compatible endpoint, or Claude

**Web:** Next.js 16 (App Router, Server Actions) · React 19 · TypeScript ·
Drizzle · PGlite / Postgres · Tailwind v4 · Zod · nodemailer

No auth library — sessions, passwords and tokens are built on `node:crypto`.
No Redis, no queue, no component library. Few dependencies, each earning its
place.

## Checks

```bash
python -m job_scout.tests                          # 62 checks
npm run check --prefix jobscout-web                # 80 checks
node jobscout-web/scripts/check-deletion.mjs       # account deletion cascade
```

The web checks cover inbox parsing and routing, the rules that decide whether
a tracker row moves, and the account layer — that an unconfirmed address
cannot sign in, that a missing account costs the same time as a wrong
password, the lockout, and that a reset drops every session.

## Notes

- Passwords: scrypt, salted, parameters stored with the hash and re-hashed
  when raised. No form reveals whether an address has an account.
- Everything personal references `users.id` with `ON DELETE CASCADE`, so
  "delete my account" is one statement and total. Job postings are public
  listings and survive.
- Forwarded mail is truncated on the way in and deleted after
  `INBOX_RETENTION_DAYS`. This is a tracker, not a mail archive.
